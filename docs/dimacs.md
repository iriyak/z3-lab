# DIMACS CNF の取り込み

SAT ソルバの標準形式を、そのまま Z3 に解かせる。`z3lab solve problem.cnf`(拡張子 `.cnf` で判定)、
`z3lab solve --dimacs -`(標準入力)、MCP ツールの `dimacs` 引数(本文)と `spec`(lab 内の `.cnf`)。

```text
c コメント行
p cnf 3 3        ← 変数 3、節 3
1 2 0            ← (x1 ∨ x2)。0 で節が終わる
-1 3 0           ← (¬x1 ∨ x3)
-2 -3 0          ← (¬x2 ∨ ¬x3)
```

## 変換(`lib/dimacs.ts`)

- 変数 `N` は Bool 定数 `vN`(`(declare-const vN Bool)`)。節は `(assert (or ...))`。リテラル `-N` は `(not vN)`。
- 単位節は `(assert vN)`、空の節は `(assert false)`(これだけで unsat)。
- 読み方は厳格。`c` で始まる行はコメント、`p cnf V C` のヘッダが要る、`%` で読み終わる(SATLIB の流儀)、
  1 つの節が複数行にまたがってよい、BOM は除く。リテラルの範囲、ヘッダの節の数との一致、最後の節が `0` で終わっているかを検査し、
  誤りは `status: "error"` と、何が悪いかのメッセージで返す。

## 出力

- テキスト(CLI): `s SATISFIABLE` と、割り当ての `v 1 -2 3 0`(約 78 文字で折り返す)、または `s UNSATISFIABLE`。
- `--json` / MCP: 通常の結果に `dimacs: { variables, clauses, assignment }` が付く(`model` は付かない)。
  `assignment` は、変数 3 が真なら `3`、偽なら `-3`。節に出てこない変数は偽として載せる。
- **sat のときは、返す前に割り当てが全節を満たすかをこちらで検査する**。満たさなければ `error`
  (「internal check failed」)にする。ソルバの出力を信じ切らない、という置き方。
- `unsatCore` は付けない(unsat のときも)。DIMACS の節には名前が無いので core は作れず、空の `[]` を返すと「何も前提にしなくても矛盾する」と読めてしまうため。
  どの節が原因かを知りたくなったら、節に名前を付けて、`dimacs.unsatClauses`(節の番号)のような専用の項目で返す案がある(未実装)。

## 終了コードの違い

z3lab の終了コードは 0 = sat、10 = unsat、11 = unknown、12 = timeout、1 = error、2 = 使い方の誤り。
SAT コンペの慣例は **10 = SAT、20 = UNSAT** で、数字の意味が逆になる箇所がある。DIMACS を使うときも z3lab の
コードのまま(コンペ用のスクリプトに繋ぐなら変換が要る)。

## 試したもの

- `examples/dimacs/`: `small-sat.cnf`、`pigeonhole-4-3.cnf`(鳩 4 羽・巣 3 つ、22 節、unsat)、
  `random-3sat-20-91.cnf`(20 変数・91 節、seed 1)。
- `compare-backends` で、ランダム 3-SAT(n=50 / 100 / 150、比 4.26、固定シード)を exe と wasm の両方で解き、判定が一致。
- **SATLIB の uf20-91**(1000 問、すべて充足可能。[ページ](https://www.cs.ubc.ca/~hoos/SATLIB/Benchmarks/SAT/RND3SAT/descr.html))を
  `bun experiments\satlib.ts work\satlib --backend wasm` で全部解いた(Windows、11/26): **1000 問すべて sat、問題 0 件**、
  全体で 28.2 秒、1 問あたりの中央値 14 ms、最大 248 ms。sat の割り当ては全節で検査済み。
- **SATLIB の uuf50-218**(1000 問、すべて充足不可能)も同じ手順で全部解いた(Windows、11/26): **1000 問すべて unsat、問題 0 件**、
  33.0 秒、中央値 18 ms、最大 374 ms。ただし `unsat` には割り当てのような検査できる証拠がなく、SATLIB が保証する「全問 unsat」と
  z3 の答えが一致した、という確認(証明そのものは検査していない)。
- **SATLIB の uf100-430 と uuf100-430**(各 1000 問、100 変数・430 節)も同じ手順で全部解いた(Windows、11/26): uf100-430 は
  **1000 問すべて sat**(56.2 秒、中央値 34 ms、最大 244 ms)、uuf100-430 は **1000 問すべて unsat**(49.6 秒、中央値 32 ms、
  最大 460 ms)。問題 0 件。変数が 50 から 100 に増えても、1 問あたりは 2 倍弱しか増えなかった。
- **uf75〜uf250 と uuf75〜uuf250**(各 100 問、14 セット)は `experiments/satlib-all.ps1` で exe バックエンド(タイムアウト 300 秒)で解いた
  (Windows、11/26 23:50〜11/27 00:22、約 31 分)。**uf は全問 sat、uuf は全問 unsat、問題 0 件、timeout 0 件**。
  uuf200-860 だけ 99 件だった(ダウンロードした `.tar.gz` の中身も 99 件で、取り込みの欠けではなく、配布されているアーカイブ自体が 99 件)。1 問あたりの中央値と最大(solve のみ):

  | セット | uf 中央値 / 最大 | uuf 中央値 / 最大 |
  |---|---|---|
  | 75-325 | 72 ms / 253 ms | 72 ms / 365 ms |
  | 125-538 | 92 ms / 682 ms | 89 ms / 183 ms |
  | 150-645 | 100 ms / 366 ms | 121 ms / 260 ms |
  | 175-753 | 148 ms / 709 ms | 220 ms / 797 ms |
  | 200-860 | 212 ms / 1.4 s | 704 ms / 2.3 s |
  | 225-960 | 349 ms / 5.6 s | 2.3 s / 10.3 s |
  | 250-1065 | 1.4 s / 16.4 s | 9.7 s / 25.5 s |

  変数が 25 増えるごとに、uuf の中央値はおよそ 2〜4 倍になった(200→225 で 3.3 倍、225→250 で 4.1 倍)。uf は最大値が中央値よりずっと大きく
  (250 で 11 倍)、運よく早く見つかる問題と遅い問題の差が大きい。uuf は全部の探索が要るので、ばらつきが小さい(250 で 2.6 倍)。
  uuf250-1065 は 1 セットで 17 分かかった。
- 未確認: exe と wasm の時間比べを中規模の全セットで取ること(uuf250 の 3 問だけで測った: exe が約 1.3 倍速い)。`satlib.ts` はファイル名から期待値を決めるので、
  フォルダを置くだけで同じ手順で試せる。
